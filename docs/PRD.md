# 마이크로 PRD — 시니어 AI 이야기 영상 입문 과정 랜딩페이지

## 1. 제품 개요

- **제품 형태:** 브라우저에서 바로 열 수 있는 단일 HTML 파일(`index.html`)
- **서비스 목적:** AI를 처음 접하는 시니어가 사진과 AI 도구를 활용해 자신의 이야기를 짧은 영상으로 만들 수 있다는 점을 쉽고 안심되게 전달하고, 외부 신청서 작성으로 연결한다.
- **핵심 전환:** 페이지 하단 및 주요 지점의 `수강 신청하기` 버튼 클릭 → 외부 신청서 URL로 이동
- **콘텐츠 원칙:** 쉬운 한국어, 짧은 문장, 큰 글자와 버튼, 낯선 용어에 대한 즉시 설명을 사용한다.

## 2. 타깃 사용자와 핵심 고통

### 주요 타깃

- AI와 영상 제작 경험이 거의 없는 시니어
- 스마트폰으로 사진을 보고 공유하는 기본 조작은 가능하지만, 새로운 디지털 도구에는 부담을 느끼는 사람
- 가족, 여행, 취미, 인생 경험을 의미 있는 콘텐츠로 남기고 싶은 사람

### 핵심 고통

“AI나 영상 편집은 젊고 기술에 익숙한 사람만 할 수 있을 것 같고, 무엇부터 시작해야 할지 모르겠다.”

### 제공 가치

- 복잡한 이론보다 따라 하기 중심의 단계별 학습
- 개인 사진과 이야기를 활용한 짧은 영상 1편 완성
- 사진, AI 음성, 음악을 조합하는 전 과정을 초보자 눈높이로 안내
- 완성한 영상을 가족이나 지인에게 공유할 수 있다는 성취감 제공

## 3. 사용자 스토리

- 시니어 방문자로서, 과정이 초보자에게도 가능한지 첫 화면에서 바로 알고 싶다.
- 시니어 방문자로서, 무엇을 배우고 어떤 영상을 완성하는지 쉬운 예시로 확인하고 싶다.
- 시니어 방문자로서, 강사가 믿을 만하고 천천히 알려주는 사람인지 판단하고 싶다.
- 관심 있는 방문자로서, 과정 정보를 확인한 뒤 혼란 없이 외부 신청서로 이동하고 싶다.

## 4. PC·모바일 반응형 사용자 흐름

1. **첫 화면 진입**
   - 과정명, 한 문장 가치 제안, 강사 사진, 완성 결과물 예시 이미지를 확인한다.
   - `수강 신청하기` 버튼과 `과정 살펴보기` 버튼 중 하나를 선택한다.
2. **과정 이해**
   - 추천 대상, 3단계 제작 과정, 수강 후 완성할 영상의 구성을 확인한다.
   - 영상 예시 카드는 실제 영상 대신 썸네일과 설명으로 제공하며, 예시 링크가 준비된 경우 새 탭에서 연다.
3. **신뢰 확인 및 신청**
   - 강사의 얼굴, 경력, 교육 방식과 수강 전 안내를 확인한다.
   - `외부 신청서 작성하기` 버튼을 눌러 새 탭에서 신청 페이지로 이동한다.

### PC 동작

- 최대 콘텐츠 너비는 `1200px`, 좌우 여백은 최소 `24px`로 한다.
- 첫 화면은 소개 문구와 대표 이미지를 2열로 배치한다.
- 카드 3개는 한 줄에 배치하고, 강사 소개는 사진과 설명을 2열로 배치한다.
- 상단에는 과정명과 신청 버튼이 있는 간결한 내비게이션을 둔다.

### 모바일 동작

- `768px` 이하에서 모든 2열·3열 레이아웃을 1열로 전환한다.
- 본문 글자는 최소 `18px`, 주요 제목은 최소 `32px`, 버튼 높이는 최소 `52px`로 한다.
- 화면 하단에 `수강 신청하기` 고정 버튼을 표시하되 본문을 가리지 않도록 하단 여백을 확보한다.
- 전화번호·주소처럼 작은 정보보다 과정 결과와 신청 행동을 먼저 보여준다.

## 5. 핵심 3대 섹션

### 섹션 1. 히어로 — “내 사진과 목소리로 완성하는 첫 AI 이야기 영상”

**목적:** 방문 후 5초 안에 대상, 결과물, 난이도를 이해시키고 신청 또는 상세 탐색을 유도한다.

**필수 요소:**

- 과정명: `시니어를 위한 AI 이야기 영상 만들기`
- 헤드라인: `소중한 사진이 한 편의 이야기가 됩니다`
- 보조 문구: `AI가 처음이어도 괜찮습니다. 사진을 고르고 이야기를 적는 것부터 음성과 음악을 더하는 것까지, 천천히 함께 완성합니다.`
- 배지 3개: `AI 완전 초보`, `따라 하기 수업`, `짧은 영상 1편 완성`
- 기본 버튼: `수강 신청하기` → 외부 신청서
- 보조 버튼: `과정 살펴보기` → 섹션 2로 부드럽게 스크롤
- 대표 비주얼: 시니어 수강생이 자신의 사진으로 만든 영상을 보는 따뜻한 분위기의 이미지

### 섹션 2. 과정과 결과물 — “세 단계면 나만의 영상이 완성됩니다”

**목적:** 막연한 기술 부담을 구체적이고 쉬운 제작 단계로 바꾼다.

**필수 요소:**

- 3단계 카드:
  1. `사진과 이야기 고르기` — 가족, 여행, 취미 사진 중 주제를 정하고 짧은 문장을 작성한다.
  2. `AI로 음성과 분위기 만들기` — 작성한 이야기에 어울리는 AI 음성과 음악을 선택한다.
  3. `짧은 영상으로 완성하기` — 사진, 음성, 음악을 합쳐 공유 가능한 영상 1편을 완성한다.
- 결과물 예시 카드: 썸네일, 제목 예시(`나의 첫 제주 여행 이야기`), 예상 길이(`1~3분`), 포함 요소(`사진·AI 음성·음악`)
- 안심 문구: `어려운 전문 용어 없이, 강사의 화면을 그대로 따라 합니다.`
- 중간 CTA: `나도 영상 만들러 가기` → 외부 신청서

### 섹션 3. 강사 신뢰와 신청 — “처음 배우는 속도에 맞춰 안내합니다”

**목적:** 1인 강사의 전문성과 친근한 수업 방식을 보여주고 최종 신청을 유도한다.

**필수 요소:**

- 강사 프로필 사진, 이름, 한 줄 소개
- 경력 또는 신뢰 근거 최대 3개
- 교육 약속 3개: `한 단계씩 설명`, `충분한 실습 시간`, `완성할 때까지 안내`
- 수강 전 안내: 권장 준비물, 과정 시간, 진행 방식 — 확정 정보로 교체 가능한 텍스트 영역
- 최종 CTA 제목: `당신의 이야기를 영상으로 남겨보세요`
- 최종 버튼: `외부 신청서 작성하기` → 새 탭에서 외부 신청서 열기
- 안내 문구: `버튼을 누르면 과정 신청서를 작성할 수 있는 새 화면이 열립니다.`

## 6. 기능 요구사항

### 필수 기능

- 상단 로고/과정명 클릭 시 페이지 맨 위로 이동
- 내부 탐색 버튼 클릭 시 대상 섹션으로 부드럽게 스크롤
- 모든 신청 CTA는 동일한 외부 신청서 URL을 새 탭으로 열기
- 외부 링크에는 `target="_blank"`와 `rel="noopener noreferrer"` 적용
- 모바일 하단 고정 CTA는 `768px` 이하에서만 표시
- 이미지에 대체 텍스트 제공
- 키보드만으로 모든 링크와 버튼에 접근 가능
- 포커스 상태를 테두리 또는 배경색 변화로 명확히 표시
- 사용자의 `prefers-reduced-motion` 설정이 활성화된 경우 스크롤 및 등장 애니메이션 최소화

### 콘텐츠 변수

HTML 상단의 주석 또는 명확한 상수 영역에서 다음 내용을 쉽게 교체할 수 있어야 한다.

- 강사명과 소개
- 강사 경력 3개
- 강사 및 대표 비주얼 이미지 경로
- 과정 일정, 장소/진행 방식, 준비물
- 외부 신청서 URL
- 결과물 예시 링크

### 오류 및 예외 처리

- 신청서 URL이 비어 있거나 `#`이면 버튼 클릭 시 이동하지 않고 `신청 링크를 준비 중입니다.`라는 안내를 버튼 근처에 표시한다.
- 이미지 로딩에 실패해도 대체 텍스트와 배경색으로 레이아웃이 유지되어야 한다.
- JavaScript가 비활성화되어도 모든 본문을 읽을 수 있고 유효한 외부 링크는 작동해야 한다.

## 7. 비주얼·UX 가이드

- **분위기:** 따뜻함, 신뢰, 성취감. 지나치게 기술적이거나 미래적인 이미지는 피한다.
- **색상:** 밝은 크림색 배경, 진한 남색 본문, 따뜻한 주황색 CTA. 본문과 배경의 명도 대비는 WCAG AA 수준을 목표로 한다.
- **서체:** 시스템 한글 글꼴(`Pretendard`, `Noto Sans KR`, `Malgun Gothic`, sans-serif 순서)을 사용한다.
- **가독성:** 본문 줄 간격 `1.7` 이상, 한 줄 길이 PC 기준 약 60자 이내, 문단당 2~3문장 이내로 제한한다.
- **버튼 문구:** 행동을 명확히 표현하고 `자세히`, `확인` 같은 모호한 표현은 피한다.
- **애니메이션:** 필수 정보 전달을 방해하지 않는 짧은 페이드 효과만 선택적으로 사용한다.

## 8. 기술 구현 조건

- 결과물은 HTML, CSS, JavaScript가 모두 포함된 `index.html` 한 파일이어야 한다.
- 외부 프레임워크나 빌드 과정 없이 파일을 더블클릭해 최신 브라우저에서 실행되어야 한다.
- 실제 콘텐츠 이미지는 데이터 URI로 포함하거나, 연결 없이도 디자인이 유지되는 CSS 기반 자리 표시자를 사용한다.
- 시맨틱 태그 `header`, `nav`, `main`, `section`, `footer`를 사용한다.
- 각 핵심 섹션에 고유한 `id`를 부여한다.
- JavaScript는 부드러운 이동, 모바일 CTA 처리, 신청 링크 미설정 안내 등 최소한의 상호작용에만 사용한다.

## 9. 완료 기준

- 단일 `index.html`을 직접 열었을 때 콘솔 오류 없이 전체 콘텐츠가 표시된다.
- 핵심 3대 섹션이 정해진 순서와 내용으로 구현된다.
- 모든 신청 CTA가 동일한 URL을 사용하며 새 탭에서 열린다.
- 신청 URL이 미설정된 상태에서도 안내 메시지가 정상적으로 표시된다.
- `360px`, `768px`, `1440px` 화면 너비에서 가로 스크롤이나 콘텐츠 겹침이 없다.
- 모바일에서 본문 글자와 터치 버튼의 최소 크기가 지켜진다.
- 키보드 탭 이동 순서가 화면의 읽기 순서와 일치한다.
- 모든 이미지에 의미 있는 대체 텍스트가 있다.
- 필수 콘텐츠 변수를 한 곳에서 쉽게 찾아 교체할 수 있다.
